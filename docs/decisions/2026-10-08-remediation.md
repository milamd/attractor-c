# C remediation decisions

These decisions implement the ordered [remediation plan](../plans/2026-10-08-c-remediation-macos.md). Deployment scope changed on 2026-10-09 to Apple silicon only at the user's request.

## JSON boundary

Retain the custom implementation behind `util/json.h` for this remediation. [Jansson](https://jansson.readthedocs.io/en/latest/apiref.html) and [cJSON](https://github.com/DaveGamble/cJSON) were considered. Jansson offers integer and real types and reference-counted ownership; cJSON principally represents numbers as doubles. Introducing either would require a separate integration/build and public-symbol migration. The default build continues to require only Command Line Tools and SDK libcurl. This choice carries an ongoing parser-maintenance cost; it is not a claim that custom parsing is preferable in general.

The retained boundary requires complete input consumption, UTF-8 and surrogate validation, strict finite numbers, escaped object keys, duplicate-key rejection, 64 levels of nesting, and a 16 MiB document ceiling. Embedded NUL is rejected at C-string boundaries. Parsed numeric lexemes are retained for exact serialization, including integers exceeding double's exact-integer range; `json_get_int` only accepts integral values within `int` range. Constructed numeric values use finite doubles and locale-independent 17-digit serialization. Floating-point overflow and underflow reported by conversion are rejected. Builders consume inserted values on success and failure and have a sticky failure state. Trees must have unique ownership and remain acyclic.

## Ownership and API migration

This is a public C API/ABI change. Recompile consumers rather than combining old headers with the new library. Message and response trees own all populated strings and children; request fields and callback arguments are borrowed. `GenerateResult` owns its response; tool-call pointers and finish-reason raw text borrow from that response and expire with `generate_result_free`. `LlmError` must be zero-initialized and freed with `llm_error_free`.

Provider registration transfers ownership, including on allocation failure. Provider `close` releases nested implementation members; client teardown releases the implementation allocation, adapter name, and adapter itself. Pipeline runners borrow graphs, backends and execution environments; the CLI frees the graph after the runner. Setting an interviewer transfers its ownership to the runner; inherited runners borrow it.

`ActiveTool.execute` now receives userdata and an error output parameter. `RegisteredTool.execute` also reports failure separately from text. `ExecutionEnv.read_raw` is required for edits. `Answer.kind` distinguishes invalid input, selection, timeout, cancellation and EOF. Checkpoint save and HTTP initialization return success/failure. Bounded edge collection returns the total count and stores at most the requested capacity; callers must check the returned count before indexing a smaller buffer. Context, graph, registry, request and response layouts changed; see the public headers.

## Workflow and intentional specification differences

The reviewed upstream workflow reference is pinned at [fb57a55ed97372a27ac90102f436947e29f48426](https://github.com/strongdm/attractor/blob/fb57a55ed97372a27ac90102f436947e29f48426/attractor-spec.md), particularly sections 3.3, 3.7 and 4.6.

Conditional matches precede label, suggested-target and unconditional fallback routes. False conditions never become fallbacks. Weight and lexical order resolve competing eligible edges deterministically, including competing labels/suggestions. Failed stages can recover through an eligible conditional route, explicit suggested recovery target, or node retry/fallback target. An ordinary unconditional edge cannot conceal failure. Partial success and skipped stages may continue; retry exhaustion fails unless the node explicitly allows partial success. Goal checks use the latest outcome of visited gates. Nonterminal dead ends and budget exhaustion fail. Restart edges retain execution history and advance to their selected target within the same run.

Human gates are stricter than the upstream first-choice fallback: invalid interactive input repeats; EOF, cancellation, an invalid answer or a missing interviewer fails closed. Only a timeout may use an explicitly configured `human.default_choice`. `--auto-approve` is the explicit approval opt-in.

Forks execute complete branches sequentially to a common fan-in/terminal boundary. Branch regions must be acyclic, disjoint before their join, and unable to escape the join. Nested forks are supported within the depth budget. This implementation deliberately merges non-conflicting changed context values and preserves namespaced branch output; upstream section 3.8 does not merge branch contexts. Conflicting values fail rather than depend on scheduling. `wait_all`, `first_success`, `quorum` (strict majority), `continue` and `fail_fast` are supported; other policies fail validation. Child runners inherit backend, interviewer, callbacks, budgets and execution environment and retain their actual failed outcome. Concurrency is deferred; session/client/callback state is confined to its owner thread.

## Checkpoint version 2

A checkpoint contains canonical transformed-graph identity, a UUID run identity, committed next node, pending attempt node, latest outcomes, append-only attempt history, context, logs, completion state and owned final outcome. Human selections and retry counts are context/history entries. Branch and child sidecar checkpoints use paths scoped by parent run identity, fork/manager instance, branch and cycle. Node artifacts are supplemental and never establish recovery success.

Persist the pending attempt before a stage, resolve its transition before committing, then emit the saved event after persistence succeeds. Files use an exclusively created 0600 temporary file, checked write/flush/close, file `fsync`, atomic `renameat`, and directory `fsync`. Checkpoint policy is `IO_SYNC`. `IO_FULL_SYNC` is available to explicit utility callers and additionally requests `F_FULLFSYNC`; checkpoints do not claim power-loss guarantees beyond their selected policy. Failure before replacement preserves the previous checkpoint. A directory-sync failure after replacement reports failure although the new file may already be visible.

Validate temporary recovery state before replacing live state. Unknown versions, malformed fields, invalid references and graph mismatches are rejected. Version 1 is not migrated: it lacks enough committed routing state to reconstruct approval/failure safely. Retain old artifacts for inspection and start a new run after reconciling effects.

Exactly-once external effects are not promised. An interrupted ordinary pending stage is ambiguous and refuses automatic replay, including a human gate whose approval has not committed. Inspect the attempt, reconcile external effects and explicitly decide whether to begin a new run. A pending fork or manager can revisit its coordinator and restore committed child/branch progress; an ambiguous pending ordinary child still fails. Attempt identity is run UUID + stage/history position + retry index. Operators that need automatic external replay must supply an explicit idempotency protocol in a separate design.

## macOS deployment and trust policy

Build for arm64 with a proposed minimum macOS 13.0 deployment target. The current runtime has been tested on macOS 26.6.2; oldest-OS runtime qualification remains required before claiming the full range. Intel, universal builds and Linux release qualification are outside scope. Use the selected SDK libcurl and libSystem UUID/pthread facilities; there are no package-manager path assumptions. HTTP options use APIs available since libcurl 7.32, including the older protocol bitmask rather than requiring the 7.85 string option. The spawn-directory adapter uses availability guards for macOS 26 and the 10.15 `_np` compatibility entry point, with a local deprecation suppression.

File tools resolve relative paths against a canonical workspace root. Default local environments permit explicit outside paths, while `local_exec_env_new_policy(root, true)` rejects escapes. Descriptor-relative reads/writes/searches reject symlinks in both modes. Search uses bounded native traversal, POSIX basic regular expressions and `fnmatch`; it does not invoke a shell. New directories/files use 0700/0600. Ordinary writes preserve existing mode; artifact files explicitly use 0600. Edits replace content through the environment and preserve mode, but do not promise atomic replacement, ACL/xattr preservation across custom environments, or protection against concurrent writers.

Shell tools intentionally execute trusted shell syntax. Root configuration is not an OS sandbox. Each command has an absolute monotonic deadline, an owned process group, restrictive descriptor inheritance, bounded output, TERM/KILL escalation and direct-child reaping. Deliberately detached descendants require stronger isolation. Subprocess environments preserve PATH, HOME, TMPDIR, locale, user and terminal variables, exclude ambient API credentials and arbitrary variables, and permit explicit additions through execution configuration.
